# 合同要点归纳框架（供 AutoClaw / 任何 LLM 填写 summary.json）

> 目标：通读合同全文后，产出**可核对、可追责**的要点归纳。所有内容必须能在原文中找到依据。

## 输入

- `output/<合同名>/extract.txt`：合同全文（先完整通读一遍）
- `output/<合同名>/clauses.json` / `outline.md`：条款切分结果
- `output/<合同名>/fields.json`：正则预提取的金额、日期等线索（仅作核对清单，不得直接照抄）

## 归纳维度（与 summary_template.json 字段一一对应）

| 字段 | 维度 | 必须回答的问题 |
| --- | --- | --- |
| basic | 合同基本信息 | 名称、类型（买卖/租赁/开发/服务…）、签订日期与地点、生效条件 |
| parties | 合同主体 | 各方全称、统一社会信用代码/身份证号、法定代表人/联系人、住所 |
| subject | 标的与范围 | 卖什么/做什么，数量、规格、质量或技术标准 |
| payment | 价款与支付 | 总价（大小写并核对是否一致）、支付方式与节点、发票类型 |
| term | 履行期限与地点 | 起止时间、进度节点、履行地 |
| obligations | 双方主要义务 | 甲方义务；乙方义务（各 3-6 条） |
| acceptance | 交付与验收 | 交付物清单、验收标准与程序、异议期限、逾期视为验收条款 |
| ip_confidential | 知识产权与保密 | 成果归属、许可范围、保密义务范围与存续期 |
| breach | 违约责任 | 违约情形、违约金计算标准、赔偿范围、定金/保证金规则 |
| termination | 变更、解除与终止 | 变更程序、单方解除权、终止后结算与资料返还 |
| dispute | 争议解决 | 仲裁或诉讼（二选一是哪类）、具体仲裁机构/法院、适用法律 |
| others | 其他重要条款 | 不可抗力、通知与送达、合同份数、未尽事宜、附件清单 |
| risks | 风险提示 | 对甲方或乙方明显不利的条款（限 3-8 条），说明风险后果 |
| gaps | 信息缺口 | 空白处、待补充约定、表述模糊处（如"另行协商"） |

## 填写规则

1. **只写合同里有的**：原文未约定的维度，points 写「未约定」；不得凭常识补齐。
2. **给出处**：每个要点尽量在 `evidence` 中给条款号与 ≤30 字原文引用。
3. **金额三查**：大写与小写是否一致；数字与文字描述是否矛盾；币种是否明确。
4. **日期要绝对化**：相对期限（"签订后 30 日"）要写清起点事件。
5. **风险提示讲后果**：不写"该条款有风险"，写"若逾期交付，日违约金为合同总额 0.5%，上限缺失，累计可能超过合同额"。
6. **gaps 必填**：空白金额、待定机构、"另行协商"类表述一律收入，这是交接给人工核对的核心。
7. 语言：简体中文；每条要点一句话；不使用形容词堆砌。

## 填写步骤

1. 通读 extract.txt 全文（不分段跳读）。
2. 对照 fields.json 逐维度核对正则线索是否真实、有无遗漏。
3. 按 summary_template.json 结构填写，删除 `_说明` 字段，保存为 `summary.json`。
4. 运行 `python scripts/build_report.py output/<合同名>` 生成完整版报告。
5. 抽查：随机挑 5 个要点回到原文核对引用是否准确；有误即修正后再生成。
